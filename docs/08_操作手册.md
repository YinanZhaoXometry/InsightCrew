# InsightCrew 操作手册（10 分钟上手）

> 这份手册只解决一件事：**让系统在你自己的电脑上跑起来，并且你能看懂它在干什么。**
> 不需要 API key，不需要联网，不需要装任何第三方库（只用到 Python 标准库）。

---

## 零步：双击启动（最省事，不需要终端）

打开文件夹：

```text
<解压目录>\InsightCrew
```

里面有两个批处理文件，**双击即可运行**：

| 文件 | 作用 | 适合什么时候用 |
|---|---|---|
| **`start.bat`** | 交互式提问，跑完自动打开回放页面 | 想自己随便问、演示答辩 |
| **`demo.bat`** | 固定剧本，跑完生成 `report.html` | 录视频（输出每次都一样） |

双击 `start.bat` 后，窗口里会提示 `输入你的问题（直接回车用示例）：`，
直接按回车就行。跑完会自己打开浏览器显示这次运行的完整回放。

**注意**：如果双击后窗口一闪就消失，说明没找到 Python。
用下面「第一步」的方式，在终端里运行，就能看到具体报错。

---

## 第一步：打开终端，进到项目目录

按 `Win + R`，输入 `cmd`，回车。然后粘下面这一行：

```bat
cd <解压目录>\InsightCrew
```

确认路径对了：

```bat
dir
```

应该能看到 `ask.py`、`run_demo.py`、`agents`、`core`、`data` 这些。

---

## 第二步：跑第一次（最重要的一条命令）

```bat
python ask.py
```

它会提示你输入问题。直接按回车，用默认的「2026 年第三季度华东区的营收是多少？」。

**屏幕上会依次出现这些**（大约 1 秒内跑完，所以要往上翻）：

```
[ Profiler -> Planner  ] PROFILE      画像卡：8 个字段 / 3 条风险
[ Planner  -> Analyst  ] PLAN         v1 计划：2 步，指标=营收
  * 工具: 沙箱执行成功：a1 value=1,189,734.57 (0.1s) sum(amount)
  * 工具: L2 独立复算（SQL 路径）：1,189,734.57 vs 执行结果 1,189,734.57 → 一致
  * 工具: L3 口径校验：1/3 项满足
[ Critic   -> Planner  ] REVISE       驳回 a1：L3 / 口径不合规
[ Planner  -> Analyst  ] PLAN         v2 计划：3 步，指标=营收
  * 工具: 沙箱执行成功：a2 value=1,036,538.28
  * 工具: L3 口径校验：3/3 项满足
[ Critic   -> Reporter ] CRITIQUE     PASS（L2+L3）
```

最后会打印一段总结：

```
──────────────────────────────────────────
这次运行发生了什么
──────────────────────────────────────────
  第 1 轮        1,189,734.57   被驳回
          → [L3] 口径不合规：扣除订单优惠券金额（coupon 字段）
          → [L3] 口径不合规：扣除 refunds 表中的退款金额
  第 2 轮        1,036,538.28   通过

  差额：153,196.29（第一轮高估 14.8%）
```

紧接着浏览器会自动弹出一个页面——那是这次运行的**回放**，从上往下滚，你能看到每一句话是谁说的、什么时候驳回的、为什么驳回。

**到这一步，你已经把它跑通了。** 后面都是变着花样玩。

## 第三步：自己换问题（这是"操作"的核心）

换问题有三种方式，任选：

```bat
python ask.py                                         :: 交互式，回车用示例
python ask.py "2026年8月华南区的营收是多少？"            :: 直接问
python ask.py                                          :: 也可以双击 start.bat
```

实测这一题：**第一轮 437,701.22 被驳回 → 第二轮 385,555.26 通过**，差额 52,145.96（高估 13.5%）。

### 它认哪些问法（都实测过）

**四个指标都能算**，每个都有"模型写代码 + SQL 独立复算"两条路径：

| 问法 | 结果 | 说明 |
|---|---|---|
| `2026年第三季度华东区的营收是多少？` | 1,036,538.28 | 营收（扣券 + 扣退款） |
| `2026年第三季度华东区的订单量是多少？` | 233 笔 | 订单量（排除取消、按单号去重） |
| `2026年第三季度华东区的客单价是多少？` | 4,448.66 | 客单价 = 营收 ÷ 订单量 |
| `2026年第三季度华东区的退款率是多少？` | 9.59 % | 退款率 = 退款金额 ÷ 订单金额（券前） |
| `2026年8月华南区的营收是多少？` | 385,555.26 | |
| `八月华南区的营收是多少？`（中文月份） | 385,555.26 | |
| `上季度华东区的营收是多少？`（相对时间） | 1,036,538.28 | |
| `2026年第三季度全公司的营收是多少？` | 3,031,580.71 | 不限地区 |
| `2026年第三季度华北区的订单量是多少？` | 220 笔 | |
| `2026年第三季度华南区的客单价是多少？` | 4,546.68 | |
| `2026年9月华北区的退款率是多少？` | 8.38 % | |
| `近三个月华东区的营收是多少？`（滚动窗口） | 442,144.89 | |
| `华南和华北的营收是多少？`（多地区） | 2,891,330.55 | |
| `华东区的营收是多少？`（不说时间＝全年） | 1,452,987.10 | |
| `2026年10月华东区的营收是多少？` | 部分覆盖：只算 10-01 ~ 10-14，报告里写明已裁剪 |

**认的说法**：地区（7 个大区 / 多个大区 / 全公司）、时间（第X季度、QX、X 月、八月、上季度、本月、上个月、近N个月、今年、去年、全年）、指标（营收 / 订单量 / 客单价 / 退款率，各带别名）。

### 它答不了的问法（会明确拒绝，不会瞎算）

拒绝分四类，每一类都有固定措辞，不会临时编：

| 问法 | 系统的反应 | 拦在哪 |
|---|---|---|
| `2026年第三季度华东区的毛利率是多少？` | 答不了：数据集没有成本（cost）字段，不允许估算 | 指标字典 |
| `2026年第三季度华东区的营销费用是多少？` | 答不了：字典与数据都没有这个指标 | 指标字典 |
| `2025年12月华北区的营收是多少？` | 答不了：数据覆盖 2026-06-01 ~ 2026-10-14 | 时间覆盖 |
| `西南8月营收` | 答不了：数据中只有华东、华北、华南，没有西南的记录 | 地区取值 |
| `8月华东线上渠道营收` | 答不了：当前版本不支持按渠道下钻，强行回答会返回全渠道数字 | 维度 |
| `帮我写一首诗` | 答不了：没有任何指标或数据类词汇 | 意图 |

顺带说明数据本身：`orders.csv`（1200 单）+ `refunds.csv`（166 条退款）由 `data/make_data.py` 以 `random.seed(42)` 生成，**是合成数据，不是真实业务数据**。选合成数据是为了把"口径陷阱"（取消单 18.2%、用券单 55.9%、退款单 13.8%）埋进可控的比例里——真实数据里这三件事混在一起，没法验证系统到底抓没抓到某一层。换真实数据只需替换这两张表和 `metric_dict.json`，计算与审计代码不用改。

遇到上面这些，报告里会是：

```
## 结论
**订单量：未能给出可信结论**

- 统计范围：华东，2026-01-01 ~ 2026-12-31
## 局限与未解决项
- 本次为降级输出：问题超出当前能力范围：…（未给出数字）
```

**这一点答辩时主动讲，比被问出来强**：一个会算错却装作确定的系统，和一个会说"我算不了"的系统，后者才可信。这也顺带回答了一个常见质疑——"它会不会编数字？"

## 第四步：看"没有审计会怎样"（一条命令，最能说服人）

```bat
python ask.py "2026年第三季度华东区的营收是多少？" --compare
```

输出：

```
  无审计　    1,189,734.57　1 轮
  有审计　    1,036,538.28　2 轮

  两个答案相差 153,196.29（14.8%）
  无审计时系统只跑一轮就交付了，它没有任何机制发现自己算错。
```

**这就是你要在答辩里放的那一页。** 一条命令，两个答案，差了 15 万，代码一行都没报错。

## 第五步：三种"动手改"的实验

### 实验 A：把错误调大，看审计还抓不抓得住

打开 `data\make_data.py`，找到退款比例那一行（大约在生成退款记录的地方），把比例从 `0.17` 改成 `0.5`，存盘，然后：

```bat
python data\make_data.py
python ask.py
```

退款变大后，第一轮和正确值的差距会明显变大。**如果审计依然能抓住，说明它不是靠"差得多"才发现的，而是靠口径。**

### 实验 B：关掉第三层，看它会不会自信地交错误答案

打开 `agents\critic.py`，找到这一行（第 50 行附近）：

```python
# ---------- L3：口径合规性 ----------
```

把它下面到「判定」之间的代码全选，用 `#` 注释掉，存盘，再跑：

```bat
python ask.py
```

你会看到：系统**一轮就通过**，交付 1,189,734.57，置信度显示「高」。我实测的结果是：

```
关掉 L3 后：1,189,734.57 | 轮数 1 | 判定 PASS
```

也就是说，只保留 L1 和 L2 时，系统会**在一轮之内、以最高置信度、交付一个高估 14.8% 的数字**。

**这个对照实验是答辩的杀手锏**——两分钟能做完，评委一看就懂 L3 为什么不能省。做完记得改回来（或者 `git checkout agents/critic.py`）。

### 实验 C：改口径手册，看系统听谁的

打开 `data\metric_dict.json`，找到营收那一条的 `required_filters`，把 `subtract_refund` 那一项删掉，存盘，再跑。

系统就不再要求扣退款了——它只认手册，不认常识。这恰好说明一件事：**审计的可靠性取决于手册的质量，而手册是人写的**。这是你 limitations 一节的真实素材。

## 第六步（可选，但答辩前值得做一次）：接真模型，让它真的自己写代码

前五步用的是离线模式：编排、沙箱、审计、回放都是真的，**只有"写代码"这一步由规则生成**。想要真模型参与，需要一个 API key。

**要提供什么**：一个 OpenAI 兼容接口的 key（DeepSeek / 通义 / 智谱 / Moonshot / OpenAI 都行），以及它的 base_url 与模型名。

### 6.1 填 key（两种方式，推荐第一种）

**方式 A：写进 `.env`（双击也能生效）**

1. 在 `insightcrew` 目录里找到 `.env.example`，**复制一份，改名为 `.env`**（注意前面有个点，Windows 会让你确认扩展名，选"是"）
2. 用记事本打开，改成：

```ini
IC_API_KEY=sk-你的key
IC_BASE_URL=https://api.deepseek.com/v1
IC_MODEL=deepseek-chat
```

3. 保存。之后双击 `start.bat` 就会自动读这份配置。

**方式 B：只对当前窗口有效**（关掉窗口就失效）

```bat
set IC_API_KEY=sk-你的key
python ask.py
```

PowerShell：

```powershell
$env:IC_API_KEY="sk-你的key"
```

### 6.2 先体检，再跑题（这一步别省）

```bat
python check_api.py
```

它会做三件事：显示读到了哪把 key（打码）、显示 key 来自哪里、**真发一次请求**。三种结果：

| 输出 | 含义 | 你要做什么 |
|---|---|---|
| ✓ 通了（0.3s，20 tokens） | key、地址、模型名都对 | 继续下一步 |
| ✗ 401 | key 无效或抄漏了 | 重新复制，注意别带空格 |
| ✗ 404 | 地址或模型名不对 | 检查 base_url 是否以 `/v1` 结尾 |

体检通过后跑一道题（会花几分钱）：

```bat
python check_api.py --run
```

### 6.3 常见服务商填什么

| 服务商 | IC_BASE_URL | IC_MODEL |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

### 6.4 接上之后，哪些东西变了

| 环节 | 离线模式 | 接真模型后 |
|---|---|---|
| Profiler 画像 | 规则模板 | **模型自己读表结构写风险清单** |
| Planner 计划 | 规则生成 | **模型自己拆步骤、自己写口径开关** |
| Analyst 写代码 | 规则拼字符串 | **模型自己写 Python**，在沙箱里真跑 |
| Critic 审计 | 确定性代码 | **完全不变**（这是设计，不是偷懒） |
| Reporter 报告 | 模板 | 模板（数字禁止被改写） |

所以"接真模型"改变的是**智能来源**，不是**审计机制**。这也是答辩时最值钱的一句话：**换模型不影响审计的可信度，因为审计不依赖模型**。

### 6.5 怎么看它有没有真的在干活

1. 终端里 `v1 计划` 的步数与措辞和离线版不同——那是模型写的
2. 报告末尾 token 数不为 0（离线模式永远是 0）
3. 回放页里的代码块长得不一样

**如果第一轮就写对了（直接扣了退款），属于正常**——说明这个模型比较谨慎，此时没有"驳回重跑"的剧情。想稳定复现剧情，用离线模式（`--no-open` 那套），它每道题都故意先漏扣。

### 6.6 没有 key 也想证明"在线链路是通的"

```bat
python -m eval.mock_online_test
```

它会起一个本地假模型服务，把 HTTP → JSON 解析 → 沙箱 → 审计 → 报告整条链路真实跑一遍。输出 `在线链路 ：✓` 就说明代码接得上，只是缺一把真 key。

### 6.7 接上真模型后，你会看到两种不同的驳回

这是接真模型才有的东西，也是最能讲的一处设计：

| 驳回类型 | 日志里出现 | 谁去修 | 例子 |
|---|---|---|---|
| **L3 口径不合规** | `驳回 REVISE：层 L3` | **Planner 重新规划** | 计划没扣退款 → 改 filters |
| **L2 数字对不上** | `同层修复：计划不变，执行者按偏差重算` | **Analyst 自己重算** | 退款率分母用了扣券后的金额 → 改代码 |

为什么必须分开：口径问题 Analyst 改不出来（它不知道手册要求），
而纯实现错误 Planner 也改不出来（它改的是开关，不是分母）。
把错误路由到"能修它的那一层"，系统才收敛；否则会一路驳回直到降级。

**真实数据**：2026-11-17 用 `deepseek-chat` 跑 12 题，**12/12 全对，平均 1.08 轮**，
两道"不该答"的题（毛利率、2025 年数据）在 0 轮内被拒绝，没有产生任何数字。

### 6.8 想录一段稳定的视频？强制离线

```bat
set IC_FORCE_OFFLINE=1
python ask.py "2026年第三季度华东区的营收是多少？"
```

配了 key 也能强制走离线剧本：剧情固定（必有一次驳回）、不依赖网络、
不会被限流打断。答辩演示建议用这个，真模型留在"现场换问题"时露一手。

## 常见问题

**Q：`python` 不是内部或外部命令**
装 Python 时没勾"Add Python to PATH"。重装一次，勾上第一页底部的那个选项。

**Q：跑出来是乱码**
在终端先执行 `chcp 65001`，再跑。

**Q：浏览器没弹出来**
加 `--no-open` 参数跑，然后手动打开终端最后打印的那个 `report.html` 路径。

**Q：跑完想再看一次回放**
```bat
python -m ui.render_report runs\20261113-235040
```
把最后那段目录名换成你自己的。或者直接进 `runs` 文件夹，双击任一 `report.html`。

**Q：怎么确认它没在编数字**
打开 `runs\<时间戳>\blackboard.json`，里面存了每一版**真实执行过的代码**和**沙箱返回的数值**。代码是可以拿去单独跑的，数字对不上就说明有问题。这是"可审计"这三个字的实际含义。

## 附：报错对照（都已修复，遇到旧报错说明在跑旧副本）

| 报错 | 原因 | 处理 |
|---|---|---|
| `TypeError: unsupported operand type(s) for |: 'type' and 'NoneType'` | Python 版本低于 3.10，且源码没有 future 注解 | 已修；确认你改的是 `COMP5584\insightcrew\` 下这份代码 |
| `Fatal Python error: _Py_HashRandomization_Init` | Windows + Python 3.8，沙箱子进程缺 `SystemRoot` | 已修（沙箱会补上这个变量），或改用 3.11 |
| 双击窗口一闪就消失 | 系统没找到 Python | 用 `start.bat`（出错会停住）；或在 cmd 里跑，能看到完整报错 |
| `不是内部或外部命令 python` | PATH 里没有 Python | 试 `py ask.py`，或重装时勾选 "Add python.exe to PATH" |

**本站实测记录**（2026-11-17）：同一份代码在 Python 3.8.3 / 3.11.5 / 3.13.14 上
跑出完全相同的结论 —— `1,036,538.28`，2 轮，无降级。三个版本结果一致这件事，
本身也可以写进报告当"可复现性"的证据。
