# InsightCrew｜专业股票分析工作台 UI/UX 设计说明

请设计一套本地运行的桌面 Web 应用。使用者是需要核查交易依据、风险边界和分析成本的专业交易用户。用户选择一只股票和一个分析日期，先确认成本，再观察多智能体协作，最后取得一份可追溯的交易结论。所有动作标签表达研究建议。主界面的操作范围是发起、观察、核查、续跑、回放和导出。

## 1. 页面地图与阅读顺序

采用 **2 个核心页面、1 种历史回放模式、1 个共享详情抽屉**。应用顶栏左侧为 InsightCrew 和「分析工作台」，右侧显示当前运行状态与「新建分析」。底部历史列表是进入既有运行的固定入口。查看历史时，如后台仍有运行，保留「返回进行中的分析」。

| 页面或模式 | 用户来这里解决什么问题 | 主要区域 |
| --- | --- | --- |
| 新建分析 | 我在分析哪一天的哪只股票？有哪些数据，最多花多少？ | 标的与日期、演示场景、高级配置、预估与确认 |
| 分析工作台 | 结论是什么？形成到哪一步？依据可靠吗？ | 运行标识、结论卡、阶段流水线、三个追问 Tab、底部历史 |
| 历史回放（工作台只读模式） | 当时依据哪些信息作出判断？哪个事件改变了方案？ | 同一套工作台、播放控制、事件时间轴、报告与静态回放导出 |

工作台首屏优先放结论。阶段流水线紧贴结论下缘，仍处于顶部观察区。默认打开「为什么」。点击引用或审计节点时保留当前标的、分析日期、所选 Tab 和滚动位置。

## 2. 页面一｜新建分析

桌面采用左侧配置、右侧预估的双栏布局，约 7∶5。左侧只把股票代码和分析日期作为首要输入。股票选择器展示代码、名称、市场；日期字段明确标为「分析截至日期」，与运行启动时间分开。提供「选择演示场景」，选择后回填表单并允许检查配置。

将组合、证据通道、评审团开关、辩论轮数、工具及记忆选项放入可展开的「分析配置」。收起时用一行摘要显示已启用项。表单主要按钮为「查看花费预估」。

右侧预估由上至下显示：

1. 本次配置摘要，以及将运行和将跳过的阶段。
2. 典型调用次数、调用次数上限、成本上限及币种。将“预计”与运行后的“已发生”用词区分。
3. 截至所选日期的数据覆盖表。列为证据通道、覆盖状态、可用日期或范围、缺失原因。覆盖不足时按系统返回结果呈现能否启动及原因。
4. 「确认预估并开始」。修改影响预估的字段后，将旧结果标记为「配置已变更，请重新预估」。提交启动后立即锁定按钮，直到收到运行结果或错误。已有活跃运行时显示其标的、日期和「查看当前运行」。用户在浏览历史期间同样受单运行限制。

## 3. 页面二｜分析工作台

**运行标识行**显示股票代码与名称、市场、分析截至日期、运行状态。运行 ID 和实际启动时间以次要文字展示。运行期间提供「取消运行」，确认层写清已发生费用和可续跑性。用户确认后等待系统回报，再切换为已中断。

**结论卡**在顶部通栏展示。第一行左侧为评级与建议动作，右侧为交付状态；第二行为入场价或区间、止损、目标、建议仓位四个对齐的数值字段。价格保留币种，仓位带比例及系统提供的计算口径。下方左列列出主要论点，每条句末紧跟引用 ID；右列列出失效条件，便于对照“什么情况下要重新评估”。评级、动作和交付状态各自独立编码。若动作本身无需入场价，展示「不适用」及原因；若应有数据但未取得，展示「缺失」及原因。

**阶段流水线**按分析师、 多空辩论、经理定论、交易员方案、独立审计、风险辩论、评审团表决排列。节点用图标和文字区分等待、进行中、完成、被打回、跳过。回退时在审计节点下显示「退回交易员 · 修订 v2」等实际路由，并保留前次审计记录。阶段下方仅展开当前活跃角色，每行含角色名、工作状态与独立计时器。模型调用期间保持布局稳定，只更新计时；收到真实产出事件后再增添卡片。

### Tab 1｜为什么 · 分析过程

按时间与阶段浏览，默认展开当前阶段或最近一次影响结论的审计事件。并行分析师以等宽卡片并排，卡片展示职责、核心发现、引用和耗时。多空辩论按轮次排列，每轮左右对应多方与空方；经理定论单独成段，显示其采纳的论点。交易员方案显示版本。风险辩论沿用轮次结构；评审团显示实际票数、结果以及可查看的意见。跳过的阶段保留在原位并说明配置原因。

**独立审计采用可展开的版本对照块。** 标题先回答哪版方案因何被否决、退回给谁；正文逐字段比较原案和修订；底部独立显示复审结果。「已提交修订」和「复审通过」分别由对应事件触发。多轮打回按发生顺序保留版本链。以下为设计演示数据：

| 核查项 | v1 被否决 | 规则限额 | v2 修订 | 复审 |
| --- | ---: | ---: | ---: | --- |
| 单一标的仓位 | 8% | ≤ 5% | 5% | 通过 |
| 止损价（USD） | 96.00 | 不适用此仓位规则 | 96.00 | 沿用原案 |

否决说明示例：「单一标的仓位高出上限 3 个百分点。已退回交易员调整仓位。」点击规则 ID 可核查限额来源；点击 v1 或 v2 可核查该版本的完整方案。修订未返回时，v2 栏显示「等待交易员提交」，原案继续可读。

### Tab 2｜能信吗 · 证据与规则

上半区为证据表，列为 ID、事实或新闻摘要、值与单位、数据日期、来源、引用者。点击结论里的引用小片，直接在右侧抽屉定位相应事实或新闻原文；抽屉内保留来源链接、引用角色、对应论点及方案版本。点击引用者可返回到具体卡片和轮次，实现双向核查。

下半区为规则表，列为规则名称、适用方案版本、阈值与比较符、实际值、判定及原因。仓位规则应直接呈现「8% / 上限 5%」这样的可核查数值。无法取得实际值时，显示「缺失 · 原因」及「无法判定」。历史审计按当次方案版本展示，防止修订后的数值覆盖原始否决依据。

### Tab 3｜花了多少 · 成本与耗时

顶部以「累计费用 / 本次预估上限」和占比条展示预算使用情况，同时列出已记录调用数、Token 和运行历时。中部按角色列出调用次数、输入/输出 Token、费用及耗时。下部瀑布图使用同一时间轴绘制各角色调用区间，重叠横条表示并行；点击区间打开对应调用事件。运行历时取实际时间跨度，角色耗时按各自记录显示。中断时保留累计费用，续跑后沿同一运行继续累计。尚未收到计量的调用标记「等待计量」。

## 4. 全页面状态矩阵

| 区域 | 无运行 | 进行中 | 已完成（已交付 / 待评审） | 已中断（可续跑） |
| --- | --- | --- | --- | --- |
| 结论与操作 | 简述用途；新建分析或选演示 | 结论形成中；显示当前阶段，可取消 | 已交付显示完整结论；待评审显示具体原因与「查看未决项」，定位对应规则或证据 | 显示最后完成阶段、中断位置及「续跑此分析」 |
| 流水线与过程 | 显示折叠的流程说明 | 高亮当前阶段与真实活跃角色 | 保留完成、打回和跳过路径 | 冻结计时，区分已保存和未执行阶段 |
| 证据与规则 | 提示启动后可核查的内容 | 分批显示已返回证据与已执行核查 | 保留引用链；待评审突出未决规则 | 保留已取得数据，标注尚未执行的检查 |
| 成本与耗时 | 引导查看运行前预估 | 展示已记录用量和进行中的区间 | 显示实际汇总与预估上限 | 显示截至中断的已发生费用 |
| 历史列表 | 展示已有历史；首次使用显示入口说明 | 当前运行标记「进行中」 | 分开标记「已交付」「待评审」 | 标记「已中断 · 可续跑」 |

“被打回”是阶段事件。打回后系统仍可处于进行中；“待评审”属于运行已经结束后的交付结果。缺失、尚未运行、配置跳过、真实数值 0 使用不同文案。后端未提供缺失原因时，明确标为「缺失 · 来源未提供原因」。

## 5. 历史、回放与统一抽屉

工作台底部用紧凑列表显示标的、分析日期、运行时间、交付状态、建议动作及费用。点击行以同一工作台只读查看。历史中断记录的「续跑」是显式操作；当前已有活跃运行时，引导查看该运行。可复用历史配置预填新分析，重新经过预估确认。

回放栏显示播放/暂停、已播时间、总时长、可拖动时间轴与关键事件标记。拖到某个事件时，结论、角色产出、审计版本及费用均还原至该时刻；拖回首次否决处应只能看到 v1 与退回原因。只读模式清晰标注「历史回放」，提供「导出报告」和「导出静态回放页」。报告保留交付状态、引用、规则与版本；静态回放页使用已保存事件，离线播放时无需调用模型。

所有对象共用一个右侧抽屉，建议宽 480–560 px。标题显示对象类型、名称或 ID，主体随对象变化：角色显示结构化产出与引用；证据显示事实或新闻原文与反向引用；事件显示时间戳、阶段、角色及关联版本；模型调用记录可展开提示词与原始回复。跨对象查看时在同一抽屉内提供返回，关闭后焦点回到触发项。仅交互式引用、版本号与事件使用链接样式。

## 6. 视觉方向与关键画板

以 1440 × 960 桌面画板起稿，12 栏网格，外边距 32 px，区块间距 24 px。采用浅灰底、白色工作面、深石墨文字、克制的蓝色交互强调。主结论字号约 28–32 px，正文 14 px；价格、百分比、费用使用等宽数字并按小数点或右边缘对齐。表格使用浅分隔线和固定表头，卡片以留白区分层级。较窄窗口允许流水线横向滚动，双列论点和表单改为上下排列。

买卖方向采用明确动词，交付状态用图形加文字，区域配色可适应不同市场的红绿习惯。琥珀色提示待评审，红色仅用于否决或规则不通过。将视觉重点放在结论、数据对照和引用；K 线大图、资产盈亏与下单面板均不属于本轮界面范围。

请用同一标的、同一日期和同一组标记为「演示」的数据制作以下关键画板：

1. 无运行工作台，进入新建分析。
2. 配置完成且已取得预估，展示可确认费用与数据覆盖。
3. 运行中，显示两个并行角色与各自计时器。
4. 审计首次否决并退回，v1 可查，v2 等待提交。
5. 修订复审通过并交付，首屏展示结论，下方保留版本对照。
6. 待评审，以及中断可续跑两个状态变体。
7. 点击结论引用后打开证据抽屉，并通过反向引用定位原始角色卡。
8. 历史回放暂停在审计否决事件；另附成本 Tab 展示并行瀑布。

原型至少走通三条任务：从配置到预估确认并启动；从结论到引用原文再回到论点；从审计否决到版本对照，再拖动历史时间轴重看否决发生的时刻。检查中断续跑入口、单运行互斥、待评审原因、缺失值及两种导出入口。
